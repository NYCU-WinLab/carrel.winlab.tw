# carrel.winlab.tw

The public page for Carrel: what it does, a Claude Code demo and the install steps.

- Stack: Next.js static export, components from `@winlab` (ui.winlab.tw), Bun.
- `components/ui/terminal.tsx` and `components/claude-code.tsx` come from the WinLab registry (`npx shadcn@latest add @winlab/claude-code`). Change them in NYCU-WinLab/ui, then re-add here; change the demo content through props.
- The sign-in step draws Carrel's consent page with `@winlab/browser` and `@winlab/consent`, the same block `internal/carrel/auth.go` copies. `public/fonts/` holds the subset fonts that page loads from this origin; keep the file names. `tokens:check` skips only `app/figure.css`; everything else uses the WinLab tokens.
- `lib/demos.ts` holds the demo turns. Tool descriptions are the start of Carrel's real ones.
- `figure/art.ts` (the study-room drawing) is generated by `figure/build.mjs` with the anatomy skill: `ANATOMY_KIT=<anatomy skill dir> node figure/build.mjs --module figure/art.ts`. `components/carrel-figure.tsx` plays it; `app/figure.css` holds the kit's styles on the site background.
- `components/cluster-status.tsx` reads Carrel's public `GET /status` every 30 seconds.
- Checks: `bun run tokens:check && bun run lint && bun run typecheck && bun run format:check && bun run build`.
- Deploy: push to `main` builds `ghcr.io/nycu-winlab/carrel.winlab.tw:sha-<7>`. The gateway sends every path Carrel does not serve (`/mcp`, `/oauth/`, `/.well-known/`, `/healthz`, `/status`, `/internal/`, `/apps/`) to this image.
