# carrel.winlab.tw

The public page for Carrel: what it does, a Claude Code demo and the install steps.

- Stack: Next.js static export, components from `@winlab` (ui.winlab.tw), Bun.
- `components/terminal/` draws Claude Code's screen. Layout, glyphs, wording and colors follow Claude Code in a fresh config (no plugins, settings or statusline). Change the content through props, not the look. Check a new screen against a real `claude` run with an empty `CLAUDE_CONFIG_DIR`.
- `app/terminal.css` keeps Claude Code's xterm-256 colors and Carrel's consent page colors. `tokens:check` skips it; everything else uses the WinLab tokens.
- `lib/demos.ts` holds the demo turns. Tool descriptions are the start of Carrel's real ones.
- `public/figure/carrel.html` is generated by `figure/build.mjs` with the anatomy skill: `ANATOMY_KIT=<anatomy skill dir> node figure/build.mjs --site public/figure/carrel.html`.
- Checks: `bun run tokens:check && bun run lint && bun run typecheck && bun run format:check && bun run build`.
- Deploy: push to `main` builds `ghcr.io/nycu-winlab/carrel.winlab.tw:sha-<7>`. The gateway sends every path Carrel does not serve (`/mcp`, `/oauth/`, `/.well-known/`, `/healthz`, `/internal/`, `/apps/`) to this image.
